## 準備と安全条件

1. `docs/alpha-nuxt-setup.md` に従い、Node.js 22以上、Docker PostgreSQL、`npm ci`、`npm run db:migrate`、`npm run dev:api` と `npm run dev:web` を準備。作業用の**検証専用DB**を使用し、既存の執筆データを保護する。CIシード用 `scripts/check-http-acceptance.mjs` は既存データ入りDBに対して実行しない。
2. Discord Developer PortalでOAuth2 Redirect URLを `http://localhost:3000/api/auth/discord/callback` に登録。`.env` に `APP_ORIGIN=http://localhost:3000`、`DISCORD_CLIENT_ID`、`DISCORD_CLIENT_SECRET`、`DISCORD_AUTHOR_USER_ID`、`DATABASE_URL` を設定。秘密値、Cookie、認証コード、実ユーザーIDを証跡へ転記しない。
3. **本人のDiscordアカウント**と、作者allowlistに含まれない**別の検証アカウント**を使う。別人の認証情報を共有しない。作者認可とログイン成功を別々に判定する。
4. ブラウザの通常ウィンドウ（作者）とプライベートウィンドウ（匿名読者）を分ける。各検証の開始時刻、ブラウザ/OS、`develop` HEAD、観測結果を記録する。

## MAN-09 手動再現：Android日本語IMEとタッチ選択（未実施）

自動試験 `apps/web/browser-acceptance/mobile-touch-editor.test.mjs` は、Chromiumの `isMobile` / `hasTouch` と合成 `compositionstart/end` による境界確認であり、**実Android/OSの日本語IMEは未検証**。以下は実機で再現する操作であって合格済みの記録ではない。

1. 本人Discordで作者ログインし、テスト専用シリーズの章を開く。未公開の原稿データに対してのみ実施し、実執筆中の本文を変更しない。
2. 「前漢字後」を入力し、Android上で「漢字」だけをタッチ選択して「選択文字にルビを付ける」をタップする。「前｜漢字《よみ》後」の読み欄が選択され、ソフトキーボードで読みを置換できることを確認する。保存・再読込で文字欠落がないことも確認する。
3. 「東京」「変換候補」等の日本語をIMEで**変換中**にルビ・ページ操作が有効化されないこと、確定後に操作を再開できること、選択範囲・カーソル・Undoが破損しないことを確認する。疑似compositionイベントの合格で代替しない。
4. 章本文の一部を選択し「ページ区切りを挿入」をタップしても選択本文が消えないこと、下書き保存のみでは匿名読者に反映されず、明示公開後にのみ更新されることを別ウィンドウで確認する。
5. 同じ機種の縦向き・横向き、および可能な320/390px相当の幅で、4領域の編集・保存ボタン、旧共通Shellのナビと背景、キーボード開閉時の横はみ出しや操作不能がないことを確認する。

結果はMAN-08/09/10に機種・Android/ブラウザ/IME版・操作条件・観測結果・画像を匿名化して記録し、正式CAT Gate・旧v0.3画像比較・デザイン承認と別に判定する。
