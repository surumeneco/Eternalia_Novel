# Eternalia_Novel α版：動作確認手順

状態: **ローカルで動く検証版**。正式なNuxt 4/NestJS/PostgreSQL/Discord OAuth2運用版ではない。

## 用意するもの

- Node.js **22以上**（[公式サイト](https://nodejs.org/)）
- ダウンロードした ZIPを解凍できるPC。**この検証版ではDB・Docker・npm install不要**

## 起動（Windows）

1. ZIPを任意のフォルダに解凍する。
2. `start-alpha.cmd` をダブルクリックする。WindowsのSmartScreen警告が出る場合は内容を確認する。通常のコマンドプロンプトから `node apps\preview\src\server.mjs` と起動してもよい。
3. コンソールに2つのURLが表示される。
   - 読者: `http://127.0.0.1:4173/`
   - 作者: `http://127.0.0.1:4173/admin#key=（毎回生成される固有文字列）`
4. **作者用のURLは `#key=...` を含む全体をブラウザで開く**。そのタブで作者用画面を操作できる。
5. 終了時はコンソールで `Ctrl+C` を押すか、ウィンドウを閉じる。

macOS/Linux: `./start-alpha.sh`。または `node apps/preview/src/server.mjs`。

### 動作確認のシナリオ

1. 作者画面で **新規作成 → シリーズ** を作成。本文には説明を入力して保存。
2. シリーズ選択後 **＋ 子項目 → volume（編）**、その下に **part（部）**、さらに **chapter（章）** を追加する。章に本文を入力して保存。
3. 作者画面の各階層で順に **現在の下書きを公開版へ反映** を実行。読者画面を開き、シリーズ→章を閲覧する。
4. 公開済み章の本文を編集して **下書きを保存**。読者画面では旧版のままであることを確認。
5. 章の **公開版へ反映** を押し、再読込すると新しい本文になることを確認。
6. 上位の編を **非公開にする** → 読者から章が消える → **公開指定へ戻す** → 章が再表示されることを確認。
7. シリーズにカテゴリ/言語/年代区分を追加し、設定・単語・文法・出来事を追加してそれぞれ公開できることを確認。
8. アプリを終了・再起動して、入力した内容が保持されていることを確認。

### 任意のデモデータ

**まだ入力したデータがない状態**で `node apps/preview/src/seed.mjs` を実行してから起動すると、架空の短いサンプルを作成します。既存データがあれば拒否し、上書きしません。

## データの保存とバックアップ

- データファイル: `.local/preview-data.json`。サーバーが変更ごとにファイルへ原子的に置換保存。
- バックアップ: アプリを停止し、`.local/preview-data.json` を別の場所へコピーする。
- 初期化: **必ず別の場所にバックアップしてから** `.local/preview-data.json` を削除。次回の起動で空になる。
- 作業データはZIPを再解凍して上書きすると失われる場合があるため、`.local/` を別途保存する。

## 注意・既知の制約

- `127.0.0.1` のみで動作し、**Discord OAuth2ではなく起動時に発行するローカル専用の確認キー**で作者操作を保護する。キーを他人に渡さない。公共ネットワークやリバースプロキシ経由で公開しない。
- PostgreSQLは未接続。暫定的にJSONファイルへ保存し、将来の移行・バックアップ互換は保証しない。α版に本物の未公開原稿や秘密情報を投入しないこと。
- Nuxt/NestJSのコード骨格は同梱されるが、この起動方法は**独立したNode.jsの検証UIと検証API**。本番アプリではない。
- 書式は暫定的に `｜漢字《ふりがな》`（ルビ）と `[[page]]`（ページ区切り）を表示する。リッチテキストエディター・ページ別の公開制御はない。
- 年表の相対年はラベル表示のみ。年代区分間の厳密な換算式・同一時系列への正規化は未実装。
- 辞書の意味別語源、入力重複・音韻規則、タグ検索、削除と履歴復元、サーバー上のDiscord認証、公開URL共有、運用ログ等は未実装。
- 公開制御はAPI側で実施する。ローカルキーを持たない読者向けリクエストは下書きを返さないが、実運用上のセキュリティ監査は未実施。
- データが破損した場合のリカバリーは未実装。大事なデータを本番用途で扱わない。

## 技術的な探索的検証

```
node --version
npm run test:alpha
```

`npm run test:alpha` は TypeScriptコンパイルが必要なため、通常の開発環境では先に `npm install` が必要です。ZIPには検証用の事前コンパイル済み `packages/contracts/dist` を同梱しているため、**動作確認だけなら npm install は不要**です。

テストは探索的なNode test runnerによる確認であり、CAT-TDDの正式なTestModel / Queue / Red・Green / conformanceではありません。環境が許す場合はCAT-TDDの既定の `issue-work`→`spec-implementation` 経路へ合流します。
