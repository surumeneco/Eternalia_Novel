# 単語のスペル順・品詞フィルタと品詞マスタの表示順（Draft）

## 採用された要求と旧版との差異

現行要件正本 `100_機能仕様.md` の **LG-05・LG-07（2026-11-16利用者判断）** が規範である。

1. **単語一覧の順序**：スペル昇順のみ。品詞順や手動順への切替は不要。単語は1語につき1行のまま扱い、複数品詞を持っていても並べ替えの代表品詞を決めない。
2. **閲覧の絞り込み**：スペル・意味の検索と、品詞によるフィルタを提供する。品詞は単語一覧のソートキーではない。
3. **品詞マスタの順序**：品詞マスタは言語ごとに管理する独立した一覧。新規追加順を既定とし、作者が手動で並べ替えられる。運用上、言語の品詞が成立した順序を表現する。
4. **単語の品詞登録**：単語の意味に設定する品詞は、所属言語に既に存在する品詞マスタから選ぶ。マスタに未登録の任意品詞を単語の入力経路から作らない。1語が複数意味・複数品詞を持つことは許容する。

旧v0.3の「300_辞書共通機能.md」の「品詞、スペルでのソート順指定」は2026-11-16の解釈確認以前の表現であり、**単語一覧を品詞順で並べる要求として継承しない**。旧 `Language/Word/SelectPublicInfo` の `Spell` 昇順と、旧 `Language/Language/SelectPublicDetail` の `Dictionary_M_Class.Order` 昇順はそれぞれ**別の一覧**に適用される。旧版の文字列だけから、複数品詞の語をどの品詞でソートするかという規則を創作しない。

## 現行コードとの照合（実装済み範囲と未完了の境界）

LG-05・LG-07の採用要件に基づく変更は、読者側の辞書スペル順固定（[PR #139](https://github.com/surumeneco/Eternalia_Novel/pull/139)）、作者側の品詞マスタ手動並べ替え（[PR #140](https://github.com/surumeneco/Eternalia_Novel/pull/140)）、通常作者UIからの任意品詞入力経路の閉鎖（[PR #141](https://github.com/surumeneco/Eternalia_Novel/pull/141)）として実装済みである。それぞれの実Chromium/PostgreSQL受入はAC-67台帳と各PRのCI結果を参照し、このDraft自体を実装・正式CAT Gateの合格証拠にはしない。

**残る実装上の不整合**：`packages/contracts/src/word-meanings.ts` は `partOfSpeech` を文字列として構文検証するが、所属言語の `wordClasses` を参照しない。`packages/contracts/src/novel.ts` の `createNode` / `editNode` は意味・語源参照を検証する一方、品詞マスタへの参照検証を持たない。`language-structure.ts` のマスタ構文検査はID重複を防ぐが、品詞名の重複や既存の単語意味の参照を検証しない。したがって、**作者UIが選択式になっても、直接APIへ渡した未知の品詞や、既存の参照先を壊すマスタ改名・削除は独立した設計・試験を必要とする**。

## 既存データ・参照操作の設計境界（判断待ち）

以下は採用済みの「品詞マスタ前提」を**既存データへ適用する方式**であり、2026-11-16の利用者判断から一意には導出できない。既存データの損失や下書き・公開版の無断同時更新を伴う選択を、AI単独でConfirmedとしない。

- **新規登録の保証**：単語作成・意味追加時には、所属言語の現在の下書き品詞マスタに存在する品詞だけを受け付ける必要がある。UI制約だけでなく、Domain/APIが直接送信された品詞を検証する。意味を未登録品詞で新規保存できないこと、他言語の同名でない品詞を流用できないことが受入条件となる。
- **既存のマスタ外品詞**：旧自由入力による保存済み値は、自動削除・勝手な品詞への置換・暗黙のマスタ追加を行わない。現行UIは旧値の表示を維持する。既存不整合を含む単語の「品詞と無関係な編集」を許すか、マスタへの明示登録・再選択を求めるか、保存単位を決める必要がある。
- **品詞マスタの識別・改名**：現行の意味は品詞名の文字列を保持し、マスタは `id/name` を持つ。**案A（構造的）**：意味からマスタの安定IDを参照する形へ移行し、名称変更は参照を維持する。ただし過去の文字列値の解決と公開版スナップショット移行が必要。**案B（互換優先）**：現行の文字列参照を保持し、既存の下書き・公開版に参照がある品詞の改名・削除を拒否する。名前変更を伴う移行は別操作として設計する。どちらも品詞マスタの**順序変更**は参照値を変更しない。
- **品詞マスタの削除**：参照中の項目について、拒否・移行・論理廃止のいずれを採るかを決める。少なくとも子の意味や公開版を暗黙に書き換えず、参照切れを作らない。
- **公開境界**：品詞マスタや単語意味の下書き編集だけで、匿名読者に見える別の公開版を更新しない。独立公開の途中でマスタ名と公開語の意味が一時的に異なる場合の表示・フィルタの整合を、参照モデル選択時に確認する。
- **照合順序**：LG-07が承認したのは「スペル昇順」。Unicode正規化、創作言語固有の照合規則、大小文字の扱い、異言語横断の一列合成順は別設計であり、無断で追加要件としない。現在の `localeCompare(..., 'ja')` は採用済みの実装方式として検証対象に留める。

**ユーザー判断が必要な主要選択**：品詞参照モデルを安定ID方式（案A）に移行するか、既存の名前参照を維持して参照中の改名・削除を拒否するか（案B）。既存マスタ外値の保存許可・移行は、選択後に整合の取れた方法を定める。この選択前にも、実装上明白なAPI未検証と回帰範囲の調査は独立して実施できる。

## 受入ベクトル候補

| ID | 操作 | 期待 |
| --- | --- | --- |
| DICT-01 | ある言語で登録/手動順とスペルが逆転した公開語を複数配置 | 言語内の単語一覧はスペル昇順になる。品詞マスタの並べ替えに左右されない |
| DICT-02 | 多品詞の語を含め、品詞フィルタとスペル・意味の検索を組み合わせる | 一致語だけを各1行で表示し、別言語語は混在させない |
| DICT-03 | 言語へ品詞を順次追加し、保存・再読込する | 追加順が初期順序として保持される |
| DICT-04 | 品詞マスタを手動で並べ替え、保存・再読込する | 設定した順序が保持される。公開版への反映は既定の明示公開境界に従う |
| DICT-05 | マスタが空／未登録の名前のまま、意味の品詞を入力しようとする | 通常入力から任意のマスタ外品詞を新規保存できない。既存不整合値は別途扱う |
| DICT-06 | 公開/非公開/予約/別シリーズの単語が混在する | スペル順と品詞フィルタに未公開データが現れない |

## 権威と工程

採用要件とこのDraftの区別を保つ。ユーザーはLG-05/07の単語スペル順・品詞マスタ順・品詞フィルタの意味を明示しており、**単語の品詞順ソートの承認待ちは解消**した。既実装の独立WorkにはそれぞれCAT成果物と実ブラウザ証拠がある一方、このファイル自体は独立のCAT `issue-work` 設計Draftであり、全体のProcess/PI/TCE一式や正式Closure/Model/Implementation Conformance、実機受入の合格を示さない。残るマスタ参照と過去データの整合を別Workとして扱い、未決事項を自動承認しない。
