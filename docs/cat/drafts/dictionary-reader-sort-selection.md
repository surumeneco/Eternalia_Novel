# 単語のスペル順・品詞フィルタと品詞マスタの表示順（Draft）

## 採用された要求と旧版との差異

現行要件正本 `100_機能仕様.md` の **LG-05・LG-07（2026-11-16利用者判断）** が規範である。

1. **単語一覧の順序**：スペル昇順のみ。品詞順や手動順への切替は不要。単語は1語につき1行のまま扱い、複数品詞を持っていても並べ替えの代表品詞を決めない。
2. **閲覧の絞り込み**：スペル・意味の検索と、品詞によるフィルタを提供する。品詞は単語一覧のソートキーではない。
3. **品詞マスタの順序**：品詞マスタは言語ごとに管理する独立した一覧。新規追加順を既定とし、作者が手動で並べ替えられる。運用上、言語の品詞が成立した順序を表現する。
4. **単語の品詞登録と参照モデル**：単語の意味に設定する品詞は、所属言語に既に存在する品詞マスタから選び、**品詞マスタの安定IDを保持**する。品詞名の文字列は参照の正本ではない。マスタに未登録の任意品詞を単語の入力経路から作らず、1語が複数意味・複数品詞を持つことは許容する。

旧v0.3の「300_辞書共通機能.md」の「品詞、スペルでのソート順指定」は2026-11-16の解釈確認以前の表現であり、**単語一覧を品詞順で並べる要求として継承しない**。旧 `Language/Word/SelectPublicInfo` の `Spell` 昇順と、旧 `Language/Language/SelectPublicDetail` の `Dictionary_M_Class.Order` 昇順はそれぞれ**別の一覧**に適用される。旧版の文字列だけから、複数品詞の語をどの品詞でソートするかという規則を創作しない。

## 現行コードとの照合（実装済み範囲と未完了の境界）

LG-05・LG-07の採用要件に基づく変更は、読者側の辞書スペル順固定（[PR #139](https://github.com/surumeneco/Eternalia_Novel/pull/139)）、作者側の品詞マスタ手動並べ替え（[PR #140](https://github.com/surumeneco/Eternalia_Novel/pull/140)）、通常作者UIからの任意品詞入力経路の閉鎖（[PR #141](https://github.com/surumeneco/Eternalia_Novel/pull/141)）として実装済みである。それぞれの実Chromium/PostgreSQL受入はAC-67台帳と各PRのCI結果を参照し、このDraft自体を実装・正式CAT Gateの合格証拠にはしない。

**更新対象（A案承認済み、α版の初期モデル）**：名称文字列に依存した `WordMeaning.partOfSpeech` と読者表示・フィルタを、同一言語の品詞マスタ安定IDを持つ `partOfSpeechId` に改める。作者向けの登録/編集入力、直接API、公開語投影、検索/辞書の品詞表示を一貫させる。名前変更は同じIDを維持し、公開名は公開済み言語マスタのスナップショットから解決する。**下書き名だけが変わっても匿名読者の品詞ラベルは変わらない**。参照中のIDの削除は禁止する。これはα版を確認するための現行データモデルの修正であり、旧データ変換プログラムの実装を要しない。実装・試験の合否は独立CAT Work・CI・AC台帳で判定する。

## 品詞マスタID参照の設計境界（採用済みA案）

2026-11-16の利用者回答により、**安定ID方式（旧案A）を採用**した。α版は未受入である。旧版SQL Server実データも現行サービスの移行対象として採用されていない。**移行先/移行元の現物が示されていない段階で、品詞名の文字列からIDを復元する移行機能、データ自動補完、互換用の自由入力経路を作らない**。実運用データが存在する場合の対応は、確認されたデータと改めて明示された要件を根拠に別途検討する。

- **モデル**：各意味は所属言語内の品詞マスタにある `id` を保持する。`name` は表示属性であり参照キーではない。品詞未設定は空IDで表す。品詞マスタは名称変更・順序変更でIDを維持する。
- **新規/編集**：単語・意味の作成/編集は、非空の品詞IDが所属言語の下書きマスタに存在しなければ原子的に拒否する。別言語にのみある同名品詞や他言語のIDは使用できない。
- **削除**：現在の下書きまたは公開済み単語で参照している品詞マスタIDの削除を拒否する。意味・単語の削除による参照解放は既存の論理削除ルールに従う。
- **公開分離**：意味の公開データには安定IDを保持し、表示用名称は**所属言語の公開済みマスタ**から解決する。下書きのみの改名や新規マスタ項目は読者へ露出させない。公開マスタに未登録のIDからラベルを推測しない。言語マスタを明示再公開したときだけ、当該言語を参照する公開語のラベルが新しい公開名称となる。
- **単語一覧順**：従来どおりスペル昇順のみ。品詞は一覧表示順を変えずフィルタに使う。単語の複数品詞は1語の重複表示を生まない。
- **照合方式**：スペル昇順のUnicode正規化や創作言語別照合など、ユーザー未承認の細部を無断追加しない。

### 統合・受入の制約

CAT個別WorkのGateと探索的なNode/HTTP/ブラウザ検証は別の証拠であり、統合PRのCIが成功してもCAT全体・実機受入の完了ではない。意図的に移行機能を作らないことは、実運用の既存データが無いと断定したことを意味しない。

## 受入ベクトル候補

| ID | 操作 | 期待 |
| --- | --- | --- |
| DICT-01 | ある言語で登録/手動順とスペルが逆転した公開語を複数配置 | 言語内の単語一覧はスペル昇順になる。品詞マスタの並べ替えに左右されない |
| DICT-02 | 多品詞の語を含め、品詞フィルタとスペル・意味の検索を組み合わせる | 一致語だけを各1行で表示し、別言語語は混在させない |
| DICT-03 | 言語へ品詞を順次追加し、保存・再読込する | 追加順が初期順序として保持される |
| DICT-04 | 品詞マスタを手動で並べ替え、保存・再読込する | 設定した順序が保持される。公開版への反映は既定の明示公開境界に従う |
| DICT-05 | マスタが空／未登録の名前のまま、意味の品詞を入力しようとする | マスタ外の安定ID・旧名称文字列を新規/編集保存できない。登録済みIDは名称変更でも維持する |
| DICT-06 | 公開/非公開/予約/別シリーズの単語が混在する | スペル順と品詞フィルタに未公開データが現れない |

## 権威と工程

採用要件とこのDraftの区別を保つ。ユーザーはLG-05/07の単語スペル順・品詞マスタ順・品詞フィルタの意味を明示しており、**単語の品詞順ソートの承認待ちは解消**した。既実装の独立WorkにはそれぞれCAT成果物と実ブラウザ証拠がある一方、このファイル自体は独立のCAT `issue-work` 設計Draftであり、全体のProcess/PI/TCE一式や正式Closure/Model/Implementation Conformance、実機受入の合格を示さない。マスタ参照IDは利用者による採用済みA案として扱うが、移行機能は作らない。
